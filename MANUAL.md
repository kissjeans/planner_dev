## Обзор продукта

Бот в Telegram, который автоматически раскладывает задачи проекта по людям и
дням: учитывает занятость, зависимости задач и дедлайн, считает план и
показывает, **кто что и когда** делает и где будут перегрузы. План дублируется в
Notion. Для ручных правок есть веб-доска.

Принцип: **источник правды — база бота**; Telegram и Notion — поверхности
отображения. Один процесс, одна команда, один чат.

Что входит:

- Сбор брифа проекта из чата → автоматический план под дедлайн.
- Шаблоны проекта `standard` / `lite`.
- Загрузка команды картинкой, отпуска, пересчёт плана.
- Голосовой ввод (расшифровка речи).
- Дневная сводка загрузки в чат.
- Зеркало в Notion: мастер-карточка проекта + база задач.
- Веб-доска администратора и журнал изменений.

## Часть A. Руководство пользователя

### Как начать

1. Бот уже добавлен в командный чат.
2. Отправьте `/start` — бот пришлёт краткую справку.
3. Меню команд — по кнопке «/» рядом с полем ввода.

### Команды

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и краткая справка |
| `/task <текст>` | Создать проект или задачу |
| `/load [имя]` | Загрузка команды на 14 дней (картинкой) |
| `/vacation <имя даты>` | Оформить отпуск / выходной |
| `/replan` | Пересчитать план по текущим данным |

Команды можно не печатать целиком: достаточно **упомянуть бота** (`@имя_бота`) и
написать запрос текстом.

### Создание проекта

```
/task Новый проект "Альфа", шаблон standard, дедлайн 25 июня
```

- **`standard`** — полный набор задач пресейла.
- **`lite`** — урезанный набор, когда жмут сроки.

Бот отвечает планом **кто → что → когда** + предупреждения о перегрузах. Под
планом две кнопки:

- ✅ **Зафиксировать** — сохранить план.
- ✏️ **Правка** — внести изменения.

**Прямой режим** (дедлайн задан): бот строит план под дедлайн; если недостижим —
предлагает рычаги (перейти на `lite`, добавить человека, сдвинуть дедлайн).
**Обратный режим** (дедлайн не задан): бот считает самую раннюю дату по
критическому пути и показывает её, в базу ничего не пишет.

### Правки плана

Нажмите ✏️ **Правка** и напишите изменение текстом, например
`убери задачу «Вычитка» из Альфы`. Бот копит правки в новое предложение; когда
устраивает — «ок» (или ✅) фиксирует итог.

### Отдельная задача

Опишите задачу ботом (название, кому, проект, срок) — он заведёт её и (если
подключён Notion) добавит строкой в базу задач.

### Загрузка, отпуска, пересчёт

```
/load              — загрузка всей команды на 14 дней
/load Айгуль       — по одному человеку
/vacation Айгуль 10-12 июня   — нерабочие дни + автоматический пересчёт
/replan            — пересобрать план по текущим данным
```

`/load` присылает картинку: занято против ёмкости, перегрузы — красным.

### Голосовые сообщения

Чтобы бот обработал голос:

- отправьте голосовое **в ответ (reply)** на сообщение бота, **или**
- сначала **упомяните бота** (`@имя_бота`) текстом, затем пришлите голосовое.

Бот расшифрует речь и выполнит запрос как текст.

### Кто что может

- **Любой участник командного чата** — создаёт, фиксирует, пересчитывает планы.
- **Известный участник команды** — те же права в личке с ботом.
- Посторонние вне чата — игнорируются.

### Дневная сводка

Каждый рабочий день в **10:00 (Москва)** бот публикует в чат загрузку и перегрузы.

### Связка с Notion (со стороны пользователя)

- Создание проекта → **мастер-карточка**: чеклист задач, «Бриф», «Идеи».
- Задача выполнена → **галочка** в чеклисте.
- Сброс плана → карточка архивируется.

### Админ-доска

`http://<хост>:8000` — проекты, команда, задачи, журнал (`/audit`). Не
выставляется в публичный интернет (доступ через VPN/SSH-туннель).

### Ограничения текущей версии

- Сценарий **«что-если»** в боте сейчас отключён.
- Ёмкость — дневной потолок **8 ч**; перегрузы помечаются, но не блокируют план
  и не перебалансируются автоматически.
- Single-tenant: одна команда, один чат, один процесс.

## Часть B. Подключение Telegram и Notion

Все секреты — через переменные окружения (`.env` или секрет-менеджер), не в
репозитории.

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `TEAM_CHAT_ID` | ID командного чата (членство = права на запись) |
| `ADMIN_IDS` | (опц.) Telegram user id админов через запятую |
| `NOTION_TOKEN` | Токен внутренней интеграции Notion |
| `NOTION_DATABASE_ID` | База задач Notion (синк отдельных задач) |
| `NOTION_PARENT_PAGE_ID` | Страница/база для мастер-карточек проектов |

Пусто → соответствующая синхронизация отключается, бот работает дальше.

### B.1 Telegram

1. **@BotFather** → `/newbot` → имя + username → скопировать токен в `BOT_TOKEN`.
2. **Видимость сообщений группы**: BotFather → `/setprivacy` → бот → **Disable**
   (иначе упоминания и голос-reply могут не доходить).
3. **Командный чат**: создать группу, добавить бота. Членство в чате = полные
   права; отдельного «только чтение» нет.
4. **`TEAM_CHAT_ID`**: добавить **@userinfobot** в чат, либо открыть
   `https://api.telegram.org/bot<BOT_TOKEN>/getUpdates` и взять `chat.id`
   (у групп — отрицательное число, напр. `-1001234567890`).
5. **`ADMIN_IDS`** (опц.): user id через запятую, если права нужны вне чата.
6. **Меню команд** бот публикует сам при старте — настраивать не нужно.

### B.2 Notion

Notion — поверхность отображения; правда в Postgres. Синхронизация
односторонняя и «лучшая попытка»: сбой Notion не ломает бота.

1. **Токен**: notion.so/my-integrations → **New integration** (*Internal*) →
   скопировать **Internal Integration Token** в `NOTION_TOKEN`.
2. **Что подключаем**:
   - `NOTION_DATABASE_ID` — существующая **база** задач (отдельные задачи падают
     в неё строками);
   - `NOTION_PARENT_PAGE_ID` — **страница или база**, под которой создаются
     мастер-карточки проектов (тип бот определяет сам).
3. **Расшарить с интеграцией** (иначе 403): открыть базу/страницу → **•••** →
   **Connections** → выбрать свою интеграцию. Для каждой из двух сущностей.
4. **Взять id из URL**: `…/<Название>-<32-символьный-id>?v=…` — hex без дефисов.

#### Схема базы задач

Маппер ищет колонки **по типу и имени** (жёстких названий нет). Колонок может не
быть — поле просто не заполнится. Рекомендуется:

| Поле задачи | Тип колонки | Имя ловится по |
|---|---|---|
| Название | `title` | любая title-колонка (обязательна) |
| Дедлайн | `date` | «дата», «дедлайн», «срок», «due», «deadline» |
| Исполнитель | `multi_select`/`select`/`rich_text` | «assign», «исполнит», «кому», «ответствен» |
| Проект/клиент | `multi_select`/`select`/`rich_text` | «проект», «project», «клиент», «заказчик» |
| Статус | `status`/`select` | «статус», «status» |

- Имена исполнителей/проекта подгоняются к существующим опциям (напр. «Рай» →
  «Рай Таиров»); нет опции — Notion создаёт новую.
- Новая задача получает первую опцию статуса как стартовый статус.

#### Что и когда синхронизируется

| Событие в боте | Действие в Notion |
|---|---|
| Создан проект | мастер-карточка: «Чеклист задач», «Бриф», «Идеи» |
| Задача выполнена | галочка в чеклисте (одностороннее done→✔) |
| Сброс плана | карточка архивируется |
| Захвачена отдельная задача | строка в базе задач |

## Проверка после настройки

1. `/task Новый проект "Тест", шаблон lite, дедлайн 30 июня` → бот предлагает
   план → ✅.
2. В Notion под `NOTION_PARENT_PAGE_ID` появилась карточка «Тест» с чеклистом.
3. `/load` → пришла картинка загрузки.
4. Голосовое в ответ на сообщение бота → бот расшифровал и ответил.

Notion-шаги не сработали? Проверьте токен, что база/страница **расшарена** с
интеграцией, и что id скопирован без лишних символов.
