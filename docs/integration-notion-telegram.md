# Интеграция: Telegram + Notion

Для того, кто подключает продукт. Все секреты задаются через переменные
окружения (файл `.env` или секрет-менеджер) — в репозиторий их не коммитят.

Связанные переменные окружения:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | Токен Telegram-бота от BotFather |
| `TEAM_CHAT_ID` | ID командного чата (членство = права на запись) |
| `ADMIN_IDS` | (опц.) Telegram user id админов через запятую |
| `NOTION_TOKEN` | Токен внутренней интеграции Notion |
| `NOTION_DATABASE_ID` | База задач Notion (синк отдельных задач) |
| `NOTION_PARENT_PAGE_ID` | Страница/база, под которой создаются мастер-карточки проектов |

Пустой Notion-блок → синхронизация просто отключается, бот продолжает работать
(«keyless degrade»). То же для отдельных частей: нет `NOTION_DATABASE_ID` — не
синкаются задачи; нет `NOTION_PARENT_PAGE_ID` — не создаются мастер-карточки.

---

## Часть 1. Telegram

### 1.1 Создать бота и получить токен

1. В Telegram откройте **@BotFather** → `/newbot`.
2. Задайте имя и username бота.
3. Скопируйте выданный токен → это `BOT_TOKEN`.

### 1.2 Разрешить боту видеть сообщения группы

По умолчанию бот в группе видит только команды и упоминания. Чтобы работали
упоминания и голос в ответ на сообщения:

1. BotFather → `/setprivacy` → выберите бота → **Disable**.

(Без этого `@упоминание`-сценарий и голосовые reply могут не доходить до бота.)

### 1.3 Завести командный чат

1. Создайте групповой чат команды.
2. Добавьте в него бота.
3. **Членство в этом чате = полные права** (создавать/фиксировать/пересчитывать
   планы). Отдельного «только чтение» нет — это сознательное решение для одной
   команды.

### 1.4 Узнать `TEAM_CHAT_ID`

Варианты:

- добавьте в чат **@userinfobot** / **@getidsbot** и посмотрите ID чата, **или**
- отправьте сообщение в чат и откройте
  `https://api.telegram.org/bot<BOT_TOKEN>/getUpdates` — поле `chat.id`.

ID группового чата — **отрицательное** число (например `-1001234567890`).
Запишите его в `TEAM_CHAT_ID`.

### 1.5 (Опц.) Назначить админов точечно

`ADMIN_IDS` — список Telegram **user id** через запятую. Нужен, только если
права на запись хотят давать вне командного чата. Узнать свой user id —
**@userinfobot**.

### 1.6 Меню команд

Меню (`/task`, `/load`, `/vacation`, `/replan`, `/start`) бот публикует сам при
старте (`set_my_commands`) — отдельно настраивать не нужно.

## Часть 2. Notion

Notion — это **поверхность отображения**: источник правды остаётся в Postgres.
Синхронизация односторонняя и «лучшая попытка» — сбой Notion не ломает бота.

### 2.1 Создать внутреннюю интеграцию и токен

1. Откройте **notion.so/my-integrations** → **New integration** (тип
   *Internal*).
2. Привяжите к нужному рабочему пространству.
3. Скопируйте **Internal Integration Token** → это `NOTION_TOKEN`.

### 2.2 Что подключаем — две вещи

| Что | Переменная | Куда указывает |
|---|---|---|
| База задач | `NOTION_DATABASE_ID` | существующая Notion-**база** (database), куда падают отдельные задачи строками |
| Родитель мастер-карточек | `NOTION_PARENT_PAGE_ID` | **страница** или **база**, под которой бот создаёт карточку каждого проекта |

`NOTION_PARENT_PAGE_ID` может быть и страницей, и базой — бот определяет тип сам.
Если это база, карточки проектов становятся её строками; если страница —
дочерними страницами.

### 2.3 Расшарить базу/страницу с интеграцией

Без этого Notion вернёт 403. Для **каждой** базы/страницы из 2.2:

1. Откройте её в Notion → меню **•••** (вверху справа) → **Connections** /
   **Add connections**.
2. Выберите свою интеграцию из 2.1.

### 2.4 Как взять `database_id` / `page_id`

Из URL страницы/базы. URL вида:

```
https://www.notion.so/<workspace>/<Название>-<32-символьный-id>?v=...
```

`<32-символьный-id>` (hex, без дефисов) — это и есть id. Для базы (database)
берите id из URL самой базы (часто открывается как полностраничная таблица).

### 2.5 Схема базы задач (`NOTION_DATABASE_ID`)

Маппер подбирает колонки **по типу и по имени** — жёстко зашитых названий нет,
он подстраивается под вашу базу. Колонок может не быть — тогда соответствующее
поле просто не заполняется. Рекомендуемый набор:

| Поле задачи | Тип колонки в Notion | Имя колонки (примеры, по которым ловится) |
|---|---|---|
| Название | `title` | любая title-колонка (обязательна в Notion) |
| Дедлайн | `date` | содержит «дата», «дедлайн», «срок», «due», «deadline» |
| Исполнитель | `multi_select` / `select` / `rich_text` | «assign», «исполнит», «кому», «ответствен», «assignee» |
| Проект / клиент | `multi_select` / `select` / `rich_text` | «проект», «project», «клиент», «заказчик» |
| Статус | `status` / `select` | «статус», «status» |

Детали поведения:

- Имена исполнителей/проекта **подгоняются** к существующим опциям select по
  совпадению токенов (напр. «Рай» → «Рай Таиров»). Если опции нет — Notion
  создаёт новую.
- Новая задача получает **первую** опцию статуса как стартовый статус.

### 2.6 Что и когда синхронизируется

| Событие в боте | Действие в Notion |
|---|---|
| Создан проект | создаётся мастер-карточка: «Чеклист задач», пустой «Бриф», «Идеи» |
| Задача выполнена | в чеклисте карточки ставится галочка (одностороннее done→✔) |
| Сброс плана проекта | карточка архивируется (soft-delete) |
| Захвачена отдельная задача | добавляется строкой в базу задач (`NOTION_DATABASE_ID`) |

## Часть 3. Проверка после настройки

1. `/task Новый проект "Тест", шаблон lite, дедлайн 30 июня` в командном чате →
   бот предлагает план → ✅.
2. В Notion под `NOTION_PARENT_PAGE_ID` появилась карточка «Тест» с чеклистом.
3. `/load` → пришла картинка загрузки.
4. Голосовое в ответ на сообщение бота → бот расшифровал и ответил.

Если Notion-шаги не сработали — проверьте: токен, что база/страница **расшарена**
с интеграцией (2.3), и что id скопирован без лишних символов.
